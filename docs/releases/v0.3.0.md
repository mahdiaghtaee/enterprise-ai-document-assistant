# v0.3.0 — Reliable Background Ingestion

Version 0.3.0 moves document extraction and indexing out of the upload request and completes the durable background-ingestion milestone.

## Highlights

- `POST /api/documents/upload` now returns `202 Accepted` after the file, document metadata, and initial `Pending` job are stored safely.
- An ASP.NET Core hosted worker claims jobs transactionally with PostgreSQL `FOR UPDATE SKIP LOCKED`.
- Extraction, chunking, deterministic embeddings, and pgvector writes run outside the HTTP request.
- Retry attempts are bounded and delayed through `available_at`.
- Abandoned `Processing` jobs are recovered after a configurable lease timeout.
- Graceful shutdown returns interrupted work to the queue without consuming an attempt.
- `GET /api/documents/{documentId}/processing-status` exposes lifecycle state, attempts, timestamps, controlled errors, and terminal status.
- The Web UI and demo script poll processing state before search and ask operations.

## Reliability Guarantees

Document metadata and the initial ingestion job are inserted in one PostgreSQL transaction. If persistence fails after local file storage succeeds, the stored file is deleted so it does not become an untracked orphan.

Only one active `Pending` or `Processing` job may exist for a document. Job claims and state transitions are database-backed, and semantic-index upserts remain idempotent across retries.

## Validation

The release is covered by:

- .NET unit and API integration tests;
- focused Worker tests for completion, permanent failure, transient retry, missing metadata, graceful shutdown, and invalid configuration;
- PostgreSQL lifecycle tests for claiming, completion, retry exhaustion, recovery, and status retrieval;
- enforced .NET line and branch coverage floors;
- Python lint, formatting, and endpoint tests;
- Docker Compose runtime verification of asynchronous upload, status polling, persistent search, and API restart;
- CodeQL and Dependency Review.

## Configuration

The hosted worker accepts:

- `IngestionWorker__PollInterval`
- `IngestionWorker__RetryDelay`
- `IngestionWorker__ProcessingTimeout`
- `IngestionWorker__RecoveryInterval`

Safe defaults are provided for local development.

## Upgrade Notes

Existing PostgreSQL volumes from v0.2.0 already contain the durable ingestion-job schema. Fresh volumes initialize it automatically. PostgreSQL entrypoint scripts do not rerun for existing volumes, so environments older than v0.2.0 must apply the reviewed idempotent schema scripts after backup or recreate only disposable local volumes.

Clients must now treat upload as asynchronous: read `processingStatusUrl` from the `202 Accepted` response and wait for `Completed` before expecting the new document in search results.

## Remaining Production Gaps

This release does not add authentication, authorization, document ownership, tenant isolation, audit logging, distributed observability, production model providers, or additional document formats. Do not use the current system for confidential or regulated documents until those controls are implemented.
