# v0.4.0 — Managed Tenant Security, Audit Operations, and Safe Document Processing

Version 0.4.0 consolidates the enterprise security, document-processing, audit, observability, and quality-evaluation work delivered since v0.3.0.

## Highlights

- Managed tenant lifecycle with durable memberships, invitations, deactivation/reactivation, and final-Admin protection.
- JWT authentication combined with durable membership authorization and forced PostgreSQL Row-Level Security.
- Separate API, platform-management, and privileged Worker database identities.
- Safe TXT/PDF/DOCX ingestion with signature/package validation, bounded extraction, explicit OCR-required outcomes, and optional fail-closed ClamAV scanning.
- Durable background ingestion with transactional job claiming, retries, recovery, and tenant-safe pgvector retrieval.
- Provider-neutral grounded answers with citation validation, insufficient-evidence handling, and deterministic CI evaluation.
- Tamper-evident per-tenant audit chains, bounded archival, integrity verification, retention operations, and negative mutation tests.
- OpenTelemetry tracing/metrics plus opt-in Collector, Prometheus, Grafana, Alertmanager, SLO guardrails, and incident/restore runbooks.
- Refined dependency-maintenance policy and a security pin for System.Text.Json 8.0.6.

## Upgrade Notes

Existing PostgreSQL deployments must review and apply the idempotent lifecycle/audit migrations after a verified backup because entrypoint initialization scripts do not rerun on existing volumes.

Deployments should provision separate credentials for `document_app`, `document_platform`, and `document_privileged`. The privileged Worker credential must not be exposed to the public API.

Audit retention remains disabled by default. PDF/DOCX safety limits and any malware-scanning provider must be explicitly reviewed and configured before production use.

## Security and Operational Boundary

This release substantially strengthens tenant isolation, auditability, file-processing boundaries, and operational verification. It is still a reference implementation and does not claim readiness for confidential or regulated production workloads without external identity lifecycle, managed secrets/encryption, legal retention controls, production malware operations, immutable external audit anchoring, and production-calibrated availability/recovery processes.

See `CHANGELOG.md`, `SECURITY.md`, and the operations documentation for the complete scope and known limitations.
